## 1. User Persona

### Primary Persona: Small-Scale Farmer (Solo/Family Operation)

| Attribute | Description |
|-----------|-------------|
| **Who** | Individual or family managing a small farm (1–5 fields, 10–50 plots) |
| **Goal** | Check on crop conditions remotely without visiting the field every day |
| **Context** | Uses a smartphone (mobile browser), often outdoors in bright sunlight, may have dirty/wet hands |
| **Technical skill** | Moderate — comfortable with smartphones and web apps, not a developer |
| **Usage pattern** | Daily quick check-ins (1–3 minutes); occasional deeper review of growth history |
| **Connectivity** | Variable — may be on LTE or spotty Wi-Fi; pages must load quickly on slow connections |
| **Pain point** | Currently must physically visit each section of the farm to assess crop status |

### PoC Validation Target
Identify 1–2 real users matching this persona for feedback after PoC is built.

## 2. Functional Requirements

### FR-1: Farm Layout (Read-Only for PoC)

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| FR-1.1 | Display a farm as a structured layout: Farm → Fields → Beds → Plots | Must | Static seed data; no editor in PoC |
| FR-1.2 | Each plot shows: crop type, variety, planting date, expected harvest window | Must | Pre-populated data |
| FR-1.3 | Farm Overview screen shows all plots as a grid with status indicators | Must | Single-column mobile layout |
| FR-1.4 | Plot tiles show: crop name, latest image thumbnail, status badge | Must | Status: Healthy / Slow Growth / Issue / No Data. "Thumbnail" = original image displayed at reduced CSS size, not a server-generated derivative. Server-side thumbnail generation is deferred to MVP. |
| FR-1.5 | Tap a plot tile to navigate to Plot Detail screen | Must | Hub-and-spoke navigation |

### FR-2: Image Upload (Camera Node → Cloud)

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| FR-2.1 | Accept image uploads via HTTPS POST from a camera node | Must | Simulated node for PoC |
| FR-2.2 | Upload payload: JPEG image (max 2MB), timestamp, plot ID, node ID | Must | Multipart/form-data |
| FR-2.3 | Store uploaded images in cloud object storage with metadata | Must | Plot association, timestamp, node ID |
| FR-2.4 | Return confirmation with image ID and URL on successful upload | Must | HTTP 201 response |
| FR-2.5 | Reject invalid uploads with appropriate error codes (400, 413) | Must | Missing fields, oversized images |
| FR-2.6 | Simulated camera node script that uploads sample images on a schedule | Must | Used for PoC testing and demos |

### FR-3: Image Viewing & Timeline

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| FR-3.1 | Plot Detail screen shows the latest camera image at full width | Must | 16:9 aspect ratio, responsive |
| FR-3.2 | Plot Detail shows crop metadata (type, variety, dates, notes) | Must | Below the image |
| FR-3.3 | Image History section shows a chronological grid of past images | Must | Newest first; images displayed at reduced CSS size (no server-side thumbnail generation in PoC) |
| FR-3.4 | Paginated image retrieval (cursor-based) | Must | For plots with many images |
| FR-3.5 | Tap a thumbnail to view full-size image | Should | Lightbox or dedicated view |
| FR-3.6 | Side-by-side or timeline comparison of two dates | Could | Validates growth monitoring UX |

### FR-4: Manual Tagging

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| FR-4.1 | One-tap tagging of images with preset tags: Healthy, Slow Growth, Possible Issue | Must | Three buttons on Plot Detail |
| FR-4.2 | Tags are persisted and visible on the image | Must | Badge/label on thumbnail |
| FR-4.3 | Optional free-text note per tag | Could | Simple text input |
| FR-4.4 | Status badge on Farm Overview reflects latest tag for each plot | Must | Aggregated from latest tagged image |
| FR-4.5 | When a tag is added to the latest image of a plot, `Plot.latest_status` is automatically updated to match | Must | If no images or tags exist, status is `no_data` |

### FR-5: Simulated Camera Node

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| FR-5.1 | CLI script or small program that uploads sample JPEG images to the API | Must | Configurable interval and target plot |
| FR-5.2 | Includes realistic metadata (timestamp, simulated node ID, resolution) | Must | For realistic testing |
| FR-5.3 | Supports configurable upload interval (default: every 1 hour) | Should | 1-hour default for cost/bandwidth modeling; configurable for demos |
| FR-5.4 | Handles upload failure gracefully (retry with exponential backoff) | Should | Validates error handling path |

## 4. Data Model Requirements

### Entities

```
Farm (1)
 └── Field (1..n)
      └── Bed (1..n)
           └── Plot (1..n)
                ├── CropInfo (1)
                └── Image (0..n)
                     └── Tag (0..n)
```

### Farm
| Field | Type | Notes |
|-------|------|-------|
| id | string (UUID) | Primary key |
| name | string | Farm name |
| description | string | Optional |
| created_at | ISO 8601 | |

### Field
| Field | Type | Notes |
|-------|------|-------|
| id | string (UUID) | Primary key |
| farm_id | string | FK to Farm |
| name | string | e.g., "North Field" |
| position | integer | Display order |

### Bed
| Field | Type | Notes |
|-------|------|-------|
| id | string (UUID) | Primary key |
| field_id | string | FK to Field |
| name | string | e.g., "Bed A" |
| position | integer | Display order |

### Plot
| Field | Type | Notes |
|-------|------|-------|
| id | string (UUID) | Primary key |
| bed_id | string | FK to Bed |
| label | string | e.g., "A1" |
| crop_type | string | e.g., "Tomato" |
| crop_variety | string | e.g., "Cherry Tomato" |
| planted_at | ISO 8601 date | |
| expected_harvest | ISO 8601 date | Approximate |
| notes | string | Free-text observations |
| latest_status | enum | healthy / slow_growth / issue / no_data. Auto-updated from the most recent Tag on the plot's latest image. |

### Image
| Field | Type | Notes |
|-------|------|-------|
| id | string (UUID) | Primary key |
| plot_id | string | FK to Plot |
| node_id | string | Camera node identifier |
| captured_at | ISO 8601 | When the image was taken |
| uploaded_at | ISO 8601 | When received by server |
| storage_key | string | Object storage path/key |
| content_type | string | Always "image/jpeg" for PoC; retained for future format support (WebP, PNG) |
| size_bytes | integer | File size |
| metadata | JSON | Resolution, battery %, etc. |

### Tag
| Field | Type | Notes |
|-------|------|-------|
| id | string (UUID) | Primary key |
| image_id | string | FK to Image |
| tag | enum | healthy / slow_growth / issue. Multiple Tags per Image form an audit trail; the most recent Tag determines effective status. |
| note | string | Optional free-text |
| created_at | ISO 8601 | |

## 5. API Requirements

### Endpoints (PoC)

| Method | Path | Description | Auth |
|--------|------|-------------|------|
| GET | `/api/v1/farms/{farmId}` | Farm metadata + layout structure | None (PoC) |
| GET | `/api/v1/farms/{farmId}/plots` | All plots with latest status and thumbnail | None |
| GET | `/api/v1/plots/{plotId}` | Plot detail with crop metadata | None |
| GET | `/api/v1/plots/{plotId}/images?limit=N&cursor=X` | Paginated image history | None |
| POST | `/api/v1/plots/{plotId}/images` | Upload image from camera node | None |
| GET | `/api/v1/images/{imageId}` | Image metadata + signed URL | None |
| POST | `/api/v1/images/{imageId}/tags` | Add manual tag to image | None |

### Upload Contract

```
POST /api/v1/plots/{plotId}/images
Content-Type: multipart/form-data

Fields:
  image:        JPEG file (max 2MB)
  captured_at:  ISO 8601 timestamp
  node_id:      string
  metadata:     JSON string (optional) { "resolution": "1280x720", "battery_pct": 85 }

Success: 201 Created  { "id": "...", "url": "...", "created_at": "..." }
Errors:  400 (invalid), 413 (too large), 503 (storage unavailable)
```

### Design Decisions
- REST over GraphQL (simpler for PoC)
- Signed URLs for image access (images stored in object storage)
- Cursor-based pagination (reliable for time-series data)
- Single farm assumption (no multi-tenant routing)
