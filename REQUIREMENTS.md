# REQUIREMENTS.md — LitCrop MVP

> Generated by `/cc-define` (Step 1) on 2026-03-17 (PoC), expanded 2026-03-20 (MVP)
> Scope Level: **MVP** — Deliver multi-user authenticated farm monitoring with codified infrastructure, enhanced AI, and desktop-responsive UI

---

## 1. User Persona

### Primary Persona: Small-Scale Farmer (Solo/Family Operation)

| Attribute | Description |
|-----------|-------------|
| **Who** | Individual or family managing a small farm (1-5 fields, 10-50 plots) |
| **Goal** | Check on crop conditions remotely without visiting the field every day |
| **Context** | Uses a smartphone (mobile browser), often outdoors in bright sunlight, may have dirty/wet hands |
| **Technical skill** | Moderate — comfortable with smartphones and web apps, not a developer |
| **Usage pattern** | Daily quick check-ins (1-3 minutes); occasional deeper review of growth history |
| **Connectivity** | Variable — may be on LTE or spotty Wi-Fi; pages must load quickly on slow connections |
| **Pain point** | Currently must physically visit each section of the farm to assess crop status |

### MVP Validation Target
Onboard 1-5 early adopters matching this persona. Each must be able to register, create a farm, view plots, and chat with the AI advisor independently.

### FR-11: Authentication & User Management `[MVP]`

Based on ADR-007 (AWS Cognito User Pools + JWT).

| ID | Requirement | Priority | Notes |
|----|-------------|----------|-------|
| FR-11.1 | `[MVP]` User registration with email and password | Must | Cognito User Pool with email as username; Cognito Hosted UI or custom form via `amazon-cognito-identity-js` |
| FR-11.2 | `[MVP]` Email verification on registration | Must | Cognito sends verification email (default sender, 50/day limit sufficient for 1-10 users) |
| FR-11.3 | `[MVP]` User login with email and password | Must | `ALLOW_USER_PASSWORD_AUTH` flow; returns JWT access + refresh tokens |
| FR-11.4 | `[MVP]` User logout (client-side token clearing) | Must | Clear access token from memory and refresh token from localStorage; optionally call Cognito global sign-out |
| FR-11.5 | `[MVP]` Password reset via email flow | Must | Cognito forgot-password flow: request code -> verify code -> set new password |
| FR-11.6 | `[MVP]` JWT-based API authorization via API Gateway JWT Authorizer | Must | API Gateway validates Cognito JWTs at gateway level (zero Lambda cost for auth); rejects invalid/expired tokens with 401 |
| FR-11.7 | `[MVP]` Session management in Astro SSG frontend | Must | Access tokens stored in Preact state (memory); refresh tokens in localStorage; auto-refresh before expiry |
| FR-11.8 | `[MVP]` Protected routes: all `/api/v1/*` endpoints require valid JWT | Must | Exceptions: `/health`, `/api/v1/health`, Cognito callback URLs |
| FR-11.9 | `[MVP]` Hono middleware extracts user identity (`sub`, `email`) from validated JWT claims | Must | Downstream route handlers receive user context without implementing auth logic |
| FR-11.10 | `[MVP]` Unauthenticated requests to protected endpoints return 401 Unauthorized | Must | Consistent error response: `{ "error": { "code": "UNAUTHORIZED", "message": "..." } }` |
| FR-11.11 | `[MVP]` Password policy: minimum 8 characters, mixed case + number | Must | Cognito default policy; enforced server-side |
| FR-11.12 | `[MVP]` Frontend redirects unauthenticated users to login page | Must | Auth guard on all dashboard routes; login page is the entry point for unauthenticated users |

## 4. Data Model Requirements

### Entities

```
User (1) [MVP — Cognito-managed, referenced by sub]
 └── Farm (1..n per user; 1 for MVP)
      └── Field (1..n)
           └── Bed (1..n)
                └── Plot (1..n)
                     ├── CropInfo (1)
                     └── Image (0..n)
                          ├── Tag (0..n)
                          └── Thumbnail (0..1) [MVP]

Conversation (0..n per user) [MVP]
 └── Message (1..n)
```

### User `[MVP]`

User identity is managed by Cognito. No `User` table in DynamoDB — the Cognito `sub` (UUID) is used as the user identifier across all records.

| Field | Type | Notes |
|-------|------|-------|
| sub | string (UUID) | Cognito user ID; used as `user_id` FK in Farm and Conversation records |
| email | string | Cognito-managed; available in JWT claims |

### Upload Contract

```
POST /api/v1/plots/{plotId}/images
Content-Type: multipart/form-data
Authorization: Bearer <JWT>  [MVP]

Fields:
  image:        JPEG file (max 2MB)
  captured_at:  ISO 8601 timestamp
  node_id:      string
  trigger:      string ("scheduled" | "motion")
  metadata:     JSON string (optional) { "resolution": "1280x720", "battery_pct": 85 }

Success: 201 Created  { "id": "...", "url": "...", "thumbnail_url": null, "created_at": "..." }
Errors:  400 (invalid), 401 (unauthorized) [MVP], 413 (too large), 503 (storage unavailable)
```

Note: `thumbnail_url` is initially `null` in the upload response. The thumbnail is generated asynchronously by the image processing Lambda. Subsequent GET requests will include the thumbnail URL once available.

### Chat Contract `[MVP]`

```
POST /api/v1/chat
Content-Type: application/json
Authorization: Bearer <JWT>

Request Body:
  {
    "message": "What should I plant in April?",
    "conversation_id": "optional-uuid"  // omit for new conversation
  }

Success (non-streaming): 200 OK
  {
    "reply": "Based on your location in Nagano...",
    "suggestions": ["What about tomatoes?", "Show me a planting calendar"],
    "conversation_id": "uuid",
    "tool_calls": [...]  // optional; indicates which tools were invoked
  }

Success (streaming): 200 OK with Content-Type: text/event-stream
  data: {"type": "text_delta", "text": "Based on..."}
  data: {"type": "text_delta", "text": " your location..."}
  data: {"type": "message_complete", "conversation_id": "uuid", "suggestions": [...]}

Errors: 400 (invalid), 401 (unauthorized), 429 (rate limited), 500 (LLM error)
```

### Design Decisions
- REST over GraphQL (simpler for PoC/MVP)
- Signed URLs for image access (images stored in object storage)
- Cursor-based pagination (reliable for time-series data)
- `[MVP]` Multi-user: farm ownership enforced via JWT `sub` claim matching Farm `user_id`
- `[MVP]` API Gateway JWT Authorizer handles token validation (zero Lambda cost)
- `[MVP]` Conversation history stored in DynamoDB with TTL for automatic cleanup
