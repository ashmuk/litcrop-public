Touch Target Compliance

Dots are visually 9px on mobile, but each has a transparent ::before pseudo-element of 44x44px centered on the dot to meet Apple HIG minimum touch target size. Gap between adjacent dots must be at least 12px (measured center-to-center). When dots would overlap, they stack vertically (offset by 6px) with a subtle connecting line.

Screen 3: Cross-Reference Flow

Cross-reference behavior: When the user taps a diary event dot on the Gantt chart, the app navigates to the Calendar view tab with the event's date pre-selected. The calendar scrolls to show the correct month, the date cell is highlighted, and diary entries for that date appear below. This provides a seamless bridge between the timeline overview and detailed daily entries.

WCAG 2.1 AA Compliance Checklist

  • Color contrast: All dot colors tested against both white track (light mode) and #2A2A2A track (dark mode) — minimum 3:1 for UI components
  • Dark mode contrast ratios verified separately for all bar and dot colors
  • Dots are not color-only: tooltip shows category icon + text label on hover/focus
  • All interactive elements (dots, bars, buttons) are keyboard accessible via Tab + Enter
  • Focus indicators: 3px ring in primary color, meets 3:1 contrast against adjacent colors
  • Touch targets: Dots have 44x44px invisible hit area (via ::before pseudo-element on mobile)
  • Bed labels use title attribute for truncated names; screen readers get full "Bed A1 — Tomato" label
  • Today line has aria-hidden="true" (decorative); current date conveyed via header text
  • Done pane uses aria-expanded on divider toggle for screen reader state
  • Reduce Motion: Dot highlight animation replaced with instant opacity change when prefers-reduced-motion: reduce
  • Screen reader: Each row announced as "Bed [name], [crop], [status]. [N] diary events." via aria-label
  • Keyboard: Arrow keys navigate between dots within a row; Tab moves between rows

Implementation Notes for my-builder

Data flow: The enhanced CropTimeline component receives the same beds and entries props as today, plus a new dateRange prop ({ start: Date, end: Date }) replacing the single year/month. The component computes month columns from the range. Diary event dots are positioned by calculating each entry's date as a percentage offset within the full range. The "Mark done" state should be stored in the bed record (e.g., bed.status = 'done') and persisted via API.
AspectSpecification
Component name CropTimeline (enhanced, same file)
New props dateRange: { start: Date, end: Date } — replaces year/month
onMarkDone?: (bedId: string) => void
onUndoDone?: (bedId: string) => void
onDotClick?: (entry: DiaryEntry, date: string) => void
Dot positioning formula leftPct = ((entryDate - rangeStart) / (rangeEnd - rangeStart)) * 100
Dot overlap handling When two dots are within 4px horizontal distance, offset the second vertically by +6px. Max 3 stacked dots per position; additional dots show a "+N" counter.
Scroll sync Use scrollLeft sync between active and obsolete timeline panes. Label columns use position: sticky; left: 0; z-index: 3.
Mobile detection Use CSS media query (max-width: 767px) for layout; use window.matchMedia in component to cap range at 6 months.
Cross-reference nav onDotClick callback sets URL to /diary?view=calendar&date=YYYY-MM-DD&from=gantt. DiaryPage reads these params and auto-selects the date in calendar view.
Performance Virtualize rows if bed count exceeds 20. Use will-change: transform on the scrollable timeline container. Dots are rendered as plain divs, not SVG.
Persistence "Mark done" calls PATCH /beds/:id { status: 'done' }. The bed.status field determines which pane it appears in. Collapse state of the Done section is stored in localStorage('gantt-done-collapsed').
Animation (with reduce-motion) Bed moving to Done pane: slide-down + fade (300ms).
Dot highlight on tap: scale pulse (200ms).
Done divider collapse: height transition (200ms).
All wrapped in @media (prefers-reduced-motion: no-preference).
