## 2. Error Response Catalog

All API errors follow the `ErrorResponse` envelope. The `code` field is a machine-readable constant; `message` is a human-readable description.

### Error Codes

```typescript
type ErrorCode =
  | "VALIDATION_ERROR"
  | "UNAUTHORIZED"          // [MVP] Missing, expired, or invalid JWT
  | "FORBIDDEN"             // [MVP] Reserved for future RBAC/admin-only routes (not used for ownership failures)
  | "NOT_FOUND"
  | "PAYLOAD_TOO_LARGE"
  | "UNSUPPORTED_MEDIA_TYPE"
  | "CONFLICT"
  | "INTERNAL_ERROR"
  | "SERVICE_UNAVAILABLE"
  | "BAD_CURSOR"
  | "RATE_LIMITED"            // [MVP] Too many requests (per-user/per-farm throttle)
  | "UPSTREAM_ERROR";
```

### Error Catalog

| HTTP Status | Error Code | Message Template | When It Occurs |
|-------------|-----------|-----------------|----------------|
| **401** | `UNAUTHORIZED` | `"Authentication required"` | `[MVP]` No `Authorization` header provided, or JWT is malformed/expired. Returned by API Gateway JWT Authorizer (zero Lambda cost). |
| **401** | `UNAUTHORIZED` | `"Token expired"` | `[MVP]` JWT access token has expired. Client should attempt token refresh. |
| **404** | `NOT_FOUND` | `"Farm not found: {farmId}"` | `[MVP]` Valid JWT but the `sub` claim does not match the resource owner's `user_id` — returns 404 (not 403) to prevent resource enumeration. |
| **400** | `VALIDATION_ERROR` | `"Missing required field: {field}"` | Required field omitted in request body or query |
| **400** | `VALIDATION_ERROR` | `"Invalid value for '{field}': {reason}"` | Field value fails validation (e.g., invalid UUID, out-of-range number) |
| **400** | `VALIDATION_ERROR` | `"Invalid trigger type: must be 'scheduled' or 'motion'"` | Upload with unrecognized trigger value |
| **400** | `VALIDATION_ERROR` | `"Latitude must be between -90 and 90"` | Farm creation/update with out-of-range coordinates |
| **400** | `VALIDATION_ERROR` | `"Longitude must be between -180 and 180"` | Farm creation/update with out-of-range coordinates |
| **400** | `BAD_CURSOR` | `"Invalid pagination cursor"` | Malformed or expired cursor token |
| **400** | `VALIDATION_ERROR` | `"Limit must be between 1 and 100"` | Pagination limit out of allowed range |
| **404** | `NOT_FOUND` | `"Farm not found: {farmId}"` | GET/PATCH farm with non-existent ID |
| **404** | `NOT_FOUND` | `"Plot not found: {plotId}"` | GET plot or POST image to non-existent plot |
| **404** | `NOT_FOUND` | `"Image not found: {imageId}"` | GET image or POST tag to non-existent image |
| **409** | `CONFLICT` | `"Farm already exists"` | POST farm when a farm already exists (single-farm PoC constraint) |
| **413** | `PAYLOAD_TOO_LARGE` | `"Image exceeds maximum size of 2MB"` | Upload image > 2,097,152 bytes |
| **415** | `UNSUPPORTED_MEDIA_TYPE` | `"Image must be JPEG format (image/jpeg)"` | Upload with non-JPEG content type |
| **500** | `INTERNAL_ERROR` | `"An unexpected error occurred"` | Unhandled server error |
| **502** | `UPSTREAM_ERROR` | `"Weather service temporarily unavailable"` | Open-Meteo API returns error or times out |
| **502** | `UPSTREAM_ERROR` | `"AI service temporarily unavailable"` | LLM API returns error or times out |
| **429** | `RATE_LIMITED` | `"Rate limit exceeded. Try again in {retry_after} seconds"` | `[MVP]` Per-user or per-farm rate limit exceeded (e.g., chat: 20 messages/hour) |
| **503** | `SERVICE_UNAVAILABLE` | `"Storage service unavailable"` | S3 or DynamoDB returns error |

## 3. Pagination Contract

Used by: **GET /api/v1/plots/{plotId}/images** (Endpoint #6)

### Cursor Encoding

The cursor is a **Base64url-encoded JSON** string wrapping DynamoDB's `ExclusiveStartKey`. This makes it opaque to clients while allowing the server to resume scanning.

```typescript
// Server-side: encoding
function encodeCursor(lastEvaluatedKey: Record<string, AttributeValue>): Cursor {
  const json = JSON.stringify(lastEvaluatedKey);
  return Buffer.from(json).toString("base64url");  // URL-safe base64 (no +/= padding issues)
}

// Server-side: decoding
function decodeCursor(cursor: Cursor): Record<string, AttributeValue> {
  const json = Buffer.from(cursor, "base64url").toString("utf-8");
  return JSON.parse(json);  // Returns DynamoDB ExclusiveStartKey
}
```

### Pagination Parameters

| Parameter | Type | Default | Min | Max | Description |
|-----------|------|---------|-----|-----|-------------|
| `limit` | integer | 20 | 1 | 100 | Number of items per page |
| `cursor` | string | _(none)_ | — | — | Opaque cursor from previous response's `next_cursor` |

### Paginated Response Shape

```typescript
// Example: GET /api/v1/plots/{plotId}/images?limit=5
{
  "data": [
    { /* ImageSummary */ },
    { /* ImageSummary */ },
    // ... up to `limit` items
  ],
  "meta": {
    "count": 5,             // actual number of items returned (may be < limit on last page)
    "limit": 5,             // echoed from request
    "next_cursor": "eyJQ..."  // null when this is the last page
  }
}
```

### Pagination Rules

1. **First page**: Omit `cursor` parameter entirely
2. **Next page**: Pass `next_cursor` from previous response as `cursor` query param
3. **Last page**: `next_cursor` is `null` — stop iterating
4. **Sort order**: Images sorted by `captured_at` descending (newest first)
5. **Cursor validity**: Cursors do not expire but may become invalid if underlying data is deleted
6. **Invalid cursor**: Returns `400 BAD_CURSOR`

### MVP Settings `[updated from PoC]`

```typescript
// Hono CORS middleware configuration
cors({
  origin: [
    "http://localhost:3000",            // Astro dev server
    "http://localhost:4321",            // Astro preview
    "https://*.cloudfront.net",         // CloudFront distribution (MVP)
  ],
  allowMethods: ["GET", "POST", "PATCH", "OPTIONS"],
  allowHeaders: [
    "Content-Type",
    "Accept",
    "Accept-Language",
    "Authorization",                    // [MVP] JWT Bearer token
    "X-Request-Id",                     // Client-generated request correlation ID
  ],
  exposeHeaders: [
    "X-Request-Id",
  ],
  maxAge: 86400,                        // Preflight cache: 24 hours
  credentials: true,                    // [MVP] Required for auth token handling
})
```

### Notes

- `OPTIONS` preflight is handled automatically by Hono's CORS middleware
- `[MVP]` `credentials: true` — required because the frontend sends `Authorization` headers with JWT tokens
- `[MVP]` `Authorization` added to `allowHeaders` — carries the `Bearer {accessToken}` for all protected endpoints
- `allowMethods` does not include `PUT` or `DELETE` — not used in MVP API
- At Production, replace `*.cloudfront.net` with the custom domain (e.g., `https://litcrop.example.com`)

## 4b. Authentication Contract `[MVP]`

> Based on ADR-007 (AWS Cognito User Pools + JWT) and FR-11. Authentication is handled at the API Gateway level via a JWT Authorizer — the Hono Lambda receives only validated requests with extracted user context.

### Authentication Flow

```
Client                 API Gateway              Hono Lambda
  |                        |                        |
  |-- GET /api/v1/farms --→|                        |
  |   Authorization:       |                        |
  |   Bearer eyJhbG...     |                        |
  |                        |-- Validate JWT ------→ |
  |                        |   (Cognito issuer,     |
  |                        |    audience, expiry)    |
  |                        |                        |
  |                        |-- If invalid: 401 ---→ |  (no Lambda invocation)
  |                        |                        |
  |                        |-- If valid: forward --→|
  |                        |   + JWT claims in      |
  |                        |   request context      |
  |                        |                        |
  |                        |                   Hono middleware extracts:
  |                        |                   - user.sub (UserId)
  |                        |                   - user.email
  |                        |                   Route handler checks ownership
  |                        |                        |
```

### JWT Token Format

The `Authorization` header carries a Cognito-issued JWT access token:

```
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Relevant JWT claims** (extracted by Hono middleware):

| Claim | Type | Description |
|-------|------|-------------|
| `sub` | UUID | Cognito user identifier — used as `user_id` for resource ownership |
| `email` | string | User's email address |
| `token_use` | `"access"` | Must be `access` (not `id`) |
| `exp` | number | Token expiry (Unix timestamp) |
| `iss` | string | Cognito User Pool issuer URL |
| `client_id` | string | Cognito App Client ID (validated by API GW) |

### Protected vs Public Endpoints

| Endpoint | Auth Required | Ownership Check |
|----------|:------------:|:---------------:|
| `GET /health` | No | — |
| `GET /api/v1/health` | No | — |
| `GET /api/v1/farms/{farmId}` | **Yes** | `farm.user_id == jwt.sub` |
| `POST /api/v1/farms` | **Yes** | Sets `user_id = jwt.sub` on creation |
| `PATCH /api/v1/farms/{farmId}` | **Yes** | `farm.user_id == jwt.sub` |
| `GET /api/v1/farms/{farmId}/plots` | **Yes** | `farm.user_id == jwt.sub` (via farm lookup) |
| `GET /api/v1/plots/{plotId}` | **Yes** | `plot.farm.user_id == jwt.sub` (via farm lookup) |
| `GET /api/v1/plots/{plotId}/images` | **Yes** | `plot.farm.user_id == jwt.sub` |
| `POST /api/v1/plots/{plotId}/images` | **Yes** | `plot.farm.user_id == jwt.sub` |
| `GET /api/v1/images/{imageId}` | **Yes** | `image.plot.farm.user_id == jwt.sub` |
| `POST /api/v1/images/{imageId}/tags` | **Yes** | `image.plot.farm.user_id == jwt.sub` |
| `GET /api/v1/farms/{farmId}/weather` | **Yes** | `farm.user_id == jwt.sub` |
| `POST /api/v1/chat` | **Yes** | If `farm_id` provided, ownership checked |
| `GET /api/v1/farms/{farmId}/images/{imageId}/thumbnail` | **Yes** | `image.plot.farm.user_id == jwt.sub` |

### Hono Auth Middleware

```typescript
// Middleware extracts user context from validated JWT (already verified by API Gateway)
interface AuthContext {
  user: {
    sub: UserId;       // Cognito user ID — used for ownership checks
    email: string;     // User email — for display/logging
  };
}

// Usage in route handler:
app.get("/api/v1/farms/:farmId", async (c) => {
  const { sub } = c.get("user");
  const farmId = c.req.param("farmId");
  const farm = await farmService.getFarm(farmId);
  if (!farm || farm.user_id !== sub) {
    // Return 404 (not 403) to avoid leaking resource existence
    return c.json({
      error: { code: "NOT_FOUND", message: `Farm not found: ${farmId}` }
    }, 404);
  }
  // ... return farm data
});
```

### Ownership Model

- **Farm**: `user_id` field (set to JWT `sub` on creation). All farm endpoints check this.
- **Plot**: Ownership derived via `plot → bed → field → farm → user_id`. Middleware resolves the chain.
- **Image**: Ownership derived via `image → plot → farm → user_id`.
- **Tag**: Ownership derived via `tag → image → plot → farm → user_id`.

> **Performance note**: Ownership checks require resolving the entity chain to farm. For MVP, this is an additional query per request. For Production, consider denormalizing `user_id` onto all entity types or caching the farm-user mapping.

### Authentication Error Responses

```json
// 401 — No token or invalid token (from API Gateway, not Lambda)
{
  "message": "Unauthorized"
}

// 401 — Expired token (from API Gateway)
{
  "message": "The incoming token has expired"
}

// 404 — Wrong user or resource not found (from Hono middleware — returns 404 to prevent resource enumeration)
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Farm not found: farm-001"
  }
}
```

> **Note**: API Gateway 401 responses use a simpler format (`{ "message": "..." }`) than the application's `ErrorResponse` envelope because they are generated by the gateway, not by Hono. Clients should handle both formats.

### 5.1 GET /api/v1/farms/{farmId}

**Purpose**: Retrieve farm metadata including full layout structure (fields, beds, plots).

**Handler**: `getFarm`

**Auth**: Required `[MVP]` — JWT Bearer token + farm ownership check


|-----------|----|------|----------|-------------|
| `farmId` | path | FarmId | Yes | UUID of the farm |

#### Response: 200 OK

```typescript
interface GetFarmResponse {
```

#### Errors

| Status | Code | When |
|--------|------|------|
| 401 | `UNAUTHORIZED` | `[MVP]` Missing or invalid JWT token |
| 404 | `NOT_FOUND` | `[MVP]` Farm not found or caller does not own it |
| 404 | `NOT_FOUND` | Farm ID does not exist |

#### DynamoDB Operations

1. Query `PK=FARM#{farmId}` `SK=#META` — farm metadata
2. Query `PK=FARM#{farmId}` `SK begins_with FIELD#` — all fields (sorted by position via SK)
3. For each field: Query `PK=FIELD#{fieldId}` `SK begins_with BED#` — beds
4. For each bed: Query `PK=BED#{bedId}` `SK begins_with PLOT#` — plots

> **Performance note**: This is N+1 queries. Acceptable for PoC with 2 fields / 3 beds / 6 plots. For MVP, consider denormalizing the full hierarchy into the Farm item or using BatchGetItem.

### 5.2 POST /api/v1/farms

**Purpose**: Create a new farm during onboarding.

**Handler**: `createFarm`

**Auth**: Required `[MVP]` — JWT Bearer token. Sets `user_id` from JWT `sub` claim.

#### Request

```
POST /api/v1/farms
Content-Type: application/json
Authorization: Bearer {accessToken}
```

```typescript
interface CreateFarmRequest {
  name: string;                       // required, 1-100 chars
  latitude: number;                   // required, -90 to 90
  longitude: number;                  // required, -180 to 180

  locale?: LocaleEnum;               // optional, default: "en"
  theme?: ThemeEnum;                  // optional, default: "system"
  description?: string | null;        // optional, max 500 chars
}
```

#### Validation Rules

| Field | Rule |
|-------|------|
| `name` | Required. 1-100 characters. Trimmed. |
| `latitude` | Required. Number between -90 and 90 (inclusive). |
| `longitude` | Required. Number between -180 and 180 (inclusive). |
| `elevation_m` | Optional. Number between 0 and 9000 if provided. |
| `locale` | Optional. Must be `"en"` or `"ja"`. Default: `"en"`. |
| `theme` | Optional. Must be one of `ThemeEnum` values. Default: `"system"`. |
| `description` | Optional. Max 500 characters. |

#### Response: 201 Created

```typescript
interface CreateFarmResponse {
  id: FarmId;

  climate_zone: string | null;

```

#### Errors

| Status | Code | When |
|--------|------|------|
| 400 | `VALIDATION_ERROR` | Missing/invalid fields |

### 5.4 GET /api/v1/farms/{farmId}/plots

**Purpose**: Retrieve all plots for a farm with latest status. Powers the Farm Overview screen.

**Handler**: `getFarmPlots`

**Auth**: Required `[MVP]` — JWT Bearer token + farm ownership check

#### Request

```
GET /api/v1/farms/{farmId}/plots
Authorization: Bearer {accessToken}
```

| Parameter | In | Type | Required | Description |
|-----------|----|------|----------|-------------|
| `farmId` | path | FarmId | Yes | UUID of the farm |

#### Response: 200 OK

```typescript
interface GetFarmPlotsResponse {
  data: PlotSummary[];
}

interface PlotSummary {
  id: PlotId;
  label: string;
  bed_id: BedId;                      // direct reference for navigation
  field_id: FieldId;                  // populated when bed lookup succeeds
  crop_type: string;
  crop_variety: string;
  latest_status: StatusEnum;
  latest_image: LatestImage | null;   // null if no images exist
  field_name: string;                 // denormalized for display
  bed_name: string;                   // denormalized for display
}
```

## 6. Multipart Upload Contract

### Endpoint

```
POST /api/v1/plots/{plotId}/images
Content-Type: multipart/form-data
```

### Form Fields

| Field Name | Type | Required | Validation | Description |
|------------|------|----------|------------|-------------|
| `image` | File | Yes | JPEG only (`image/jpeg`), max 2,097,152 bytes (2MB). Validated by both content-type header and JPEG magic bytes (`FF D8 FF`). | The crop image file |
| `captured_at` | string | Yes | Valid ISO 8601 date-time with timezone. Must not be in the future (tolerance: +5 minutes for clock skew). | When the camera captured the image |
| `node_id` | string | Yes | Pattern: `/^[a-zA-Z0-9_-]{1,64}$/`. Alphanumeric with hyphens and underscores. | Camera node identifier |
| `trigger` | string | Yes | Exactly `"scheduled"` or `"motion"`. | What triggered the capture |
| `metadata` | string | No | Valid JSON string if provided. Max 4KB after parsing. Must be a flat or nested object (not array/primitive). | Camera metadata as JSON string |

### Metadata JSON Schema

When the optional `metadata` field is provided, it must parse as a valid JSON object:

```typescript
// All fields optional — extensible for future sensor data
interface UploadMetadata {
  resolution?: string;          // e.g. "1280x720", "1920x1080"
  battery_pct?: number;         // 0-100 integer
  temperature_c?: number;       // ambient temp from camera node sensor
  signal_strength_dbm?: number; // LTE/WiFi signal strength
  firmware_version?: string;    // camera node firmware version
}
```

### Example Upload (cURL)

```bash
curl -X POST \
  "https://api.example.com/api/v1/plots/plot-a1/images" \
  -F "image=@photo.jpg;type=image/jpeg" \
  -F "captured_at=2026-03-17T09:00:00+09:00" \
  -F "node_id=node-north-01" \
  -F "trigger=scheduled" \
  -F 'metadata={"resolution":"1280x720","battery_pct":85}'
```

### Storage Key Generation

The server generates the S3 key from the upload context:

```
images/{farmId}/{plotId}/{YYYY}/{MM}/{DD}/{imageId}.jpg
```

Where `{YYYY}/{MM}/{DD}` is derived from `captured_at` in UTC.

### Validation Order

1. Check `Content-Type` is `multipart/form-data`
2. Check `plotId` exists (404 if not)
3. Check `image` field exists (400 if missing)
4. Check file size <= 2MB (413 if exceeded)
5. Check JPEG magic bytes `FF D8 FF` (415 if not JPEG)
6. Check required text fields: `captured_at`, `node_id`, `trigger` (400 if missing)
7. Validate field values (400 if invalid)
8. Parse `metadata` JSON if provided (400 if malformed)
9. Store to S3, write DynamoDB (503 if storage fails)

## 7. Signed URL Contract

### Generation Parameters

| Parameter | Value | Notes |
|-----------|-------|-------|
| Bucket | `litcrop-mvp-images` | S3 bucket in ap-northeast-1 |
| Key | `images/{farmId}/{plotId}/{YYYY}/{MM}/{DD}/{imageId}.jpg` | Full storage key |
| Expiry | 900 seconds (15 minutes) | Signed URL validity period |
| HTTP Method | `GET` | Read-only; no PUT or DELETE signed URLs exposed |
| Region | `ap-northeast-1` | Must match bucket region |

### Signed URL Format

```
https://litcrop-mvp-images.s3.ap-northeast-1.amazonaws.com/
  images/farm-001/plot-a1/2026/03/17/{imageId}.jpg
  ?X-Amz-Algorithm=AWS4-HMAC-SHA256
  &X-Amz-Credential=...
  &X-Amz-Date=20260317T090000Z
  &X-Amz-Expires=900
  &X-Amz-SignedHeaders=host
  &X-Amz-Signature=...
```

### Server-Side Generation (AWS SDK v3)

```typescript
import { GetObjectCommand, S3Client } from "@aws-sdk/client-s3";
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";

const s3 = new S3Client({ region: "ap-northeast-1" });

async function generateSignedUrl(storageKey: string): Promise<string> {
  const command = new GetObjectCommand({
    Bucket: "litcrop-mvp-images",
    Key: storageKey,
  });
  return getSignedUrl(s3, command, { expiresIn: 900 });
}
```

### Client Usage Rules

1. **Do not cache signed URLs** beyond 15 minutes; request a fresh one via `GET /api/v1/images/{imageId}`
2. **Signed URLs are GET-only** — clients cannot upload or delete via signed URLs
3. **Direct browser fetch** — the signed URL points directly to S3; the browser fetches the image without going through the API Lambda
4. **CORS on S3 bucket** — not required since signed URLs are simple GET requests (no preflight)

### Crop Impact Analysis

The server computes `crop_impact` by comparing forecast data against known crop temperature tolerances:

```typescript
interface CropImpact {
  type: CropImpactType;
  severity: "danger" | "warning" | "good" | "info";
  title: string;                     // e.g. "Frost Risk"
  message: string;                   // e.g. "Strawberry (C1) is frost-sensitive. Expected low: -2°C tonight."
  affected_plots: AffectedPlot[];
  forecast_trigger: {
    date: ISO8601Date;
    metric: string;                  // e.g. "temperature_min_c"
    value: number;                   // e.g. -2
    threshold: number;               // e.g. 0 (frost threshold)
  };
}

type CropImpactType =
  | "frost_risk"          // min temp < 0°C and crop is frost-sensitive
  | "heat_stress"         // max temp > 35°C and crop is heat-sensitive
  | "heavy_rain"          // daily precipitation > 30mm
  | "drought_risk"        // no precipitation forecast for 5+ consecutive days
  | "optimal_planting";   // temperature range matches crop's ideal planting conditions

interface AffectedPlot {
  plot_id: PlotId;
  label: string;
  crop_type: string;
}
```

### System Prompt Structure

The LLM receives a system prompt that injects farm context. This structure is internal (not exposed to clients) but documented here for builder reference:

```typescript
function buildSystemPrompt(farm: Farm | null, plots: Plot[]): string {
  const base = `You are a crop planning assistant for small-scale farmers.
You give practical, location-specific advice about what to grow, when to plant,
and how to manage crops. Keep answers concise and actionable.
Use Markdown formatting for readability.`;

  if (!farm) return base;

  const cropList = plots
    .map(p => `- ${p.label}: ${p.crop_type} (${p.crop_variety}), planted ${p.planted_at}`)
    .join("\n");

  return `${base}

## Farm Context
- Location: ${farm.latitude}°N, ${farm.longitude}°E
- Elevation: ${farm.elevation_m ?? "unknown"}m
- Climate zone: ${farm.climate_zone ?? "unknown"}
- Locale: ${farm.locale}

## Current Crops
${cropList || "No crops planted yet."}

Tailor your recommendations to this specific location and climate.
When suggesting planting dates, calibrate to the local frost dates and growing season.
If the user's locale is "ja", respond in Japanese.`;
}
```

### Rate Limiting (PoC)

No formal rate limiting in PoC. The LLM API's own rate limits are the effective constraint. For MVP, implement per-IP or per-farm throttling (e.g., 20 messages/hour).

### Suggestions Generation

The `suggestions` array contains 2-4 contextual follow-up prompts generated by the LLM. The system prompt instructs the LLM to end each response with a JSON block of suggestions:

```
End your response with exactly 2-4 follow-up suggestions as a JSON array
on a new line prefixed with "SUGGESTIONS:". Example:
SUGGESTIONS: ["What soil pH do tomatoes need?", "When to harvest cucumbers?"]
```

The server parses this line, strips it from the `reply`, and returns it as the `suggestions` field. If parsing fails, `suggestions` defaults to a static set:

```typescript
const DEFAULT_SUGGESTIONS = [
  "What should I plant this season?",
  "Help me plan my crop rotation",
  "What are common pests in my area?",
];
```

## 10. Thumbnail Contract `[MVP]`

> Based on FR-13 (Image Processing Pipeline). Thumbnails are server-generated 320px-wide JPEG derivatives stored alongside originals in S3.

### Thumbnail Generation Flow

```
1. Image uploaded to S3 (via POST /api/v1/plots/{plotId}/images)
2. S3 PutObject event triggers Thumbnail Lambda
3. Lambda reads original image from S3
4. Lambda resizes to 320px wide (maintaining aspect ratio) using Sharp or Jimp (FR-13.6)
5. Lambda writes thumbnail to S3 at predictable key
6. If generation fails, original image remains accessible (FR-13.5)
```

### Thumbnail Storage Key Convention (FR-13.2)

```
thumbnails/{farmId}/{plotId}/{YYYY}/{MM}/{DD}/{imageId}_thumb.jpg
```

Example:
```
Original:  images/farm-001/plot-a1/2026/03/17/550e8400.jpg
Thumbnail: thumbnails/farm-001/plot-a1/2026/03/17/550e8400_thumb.jpg
```

### Thumbnail URL in API Responses (FR-13.3)

The `thumbnail_url` field is added to:
- `LatestImage` (used in PlotSummary and GetPlotResponse)
- `ImageSummary` (used in GetPlotImagesResponse)
- `GetImageResponse`

```typescript
// Thumbnail URL generation (same as full image signed URL, different key)
thumbnail_url: string | null;  // null if thumbnail not yet generated (async pipeline)
```

**Client behavior**:
- Use `thumbnail_url` for grid displays (Farm Overview tiles, Image History) — FR-13.4
- Use `url` (full image) for full-screen viewing (Image Timeline/Viewer)
- If `thumbnail_url` is `null`, fall back to `url` with CSS sizing (backwards-compatible with PoC)

### Thumbnail Signed URL

| Parameter | Value |
|-----------|-------|
| Bucket | `litcrop-mvp-images` (same bucket, different prefix) |
| Key | `thumbnails/{farmId}/{plotId}/{YYYY}/{MM}/{DD}/{imageId}_thumb.jpg` |
| Expiry | 900 seconds (15 minutes) — same as full image |
| HTTP Method | `GET` |
