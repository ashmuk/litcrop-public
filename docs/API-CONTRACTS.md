```typescript
// ── Branded ID types ────────────────────────────────────────────

/** UUID v4 string identifying a farm */

/** UUID v4 string identifying an image */

type ISO8601 = string;  // format: "2026-03-17T09:30:00Z" or "2026-03-17T18:30:00+09:00"

// ── Enums ───────────────────────────────────────────────────────
```

## 2. Error Response Catalog

All API errors follow the `ErrorResponse` envelope. The `code` field is a machine-readable constant; `message` is a human-readable description.

## 3. Pagination Contract

Used by: **GET /api/v1/beds/{bedId}/images** (Endpoint 5.17)

### Cursor Encoding

The cursor is a **Base64url-encoded JSON** string wrapping DynamoDB's `ExclusiveStartKey`. This makes it opaque to clients while allowing the server to resume scanning.

```typescript
// Server-side: encoding
function encodeCursor(lastEvaluatedKey: Record<string, AttributeValue>): Cursor {
  const json = JSON.stringify(lastEvaluatedKey);
  return Buffer.from(json).toString("base64url");  // URL-safe base64 (no +/= padding issues)
}

// Server-side: decoding
function decodeCursor(cursor: Cursor): Record<string, AttributeValue> {
  const json = Buffer.from(cursor, "base64url").toString("utf-8");
  return JSON.parse(json);  // Returns DynamoDB ExclusiveStartKey
}
```

### Pagination Parameters

| Parameter | Type | Default | Min | Max | Description |
|-----------|------|---------|-----|-----|-------------|
| `limit` | integer | 20 | 1 | 100 | Number of items per page |
| `cursor` | string | _(none)_ | — | — | Opaque cursor from previous response's `next_cursor` |

### Paginated Response Shape

```typescript
// Example: GET /api/v1/beds/{bedId}/images?limit=5
{
  "data": [
    { /* ImageSummary */ },
    { /* ImageSummary */ },
    // ... up to `limit` items
  ],
  "meta": {
    "count": 5,             // actual number of items returned (may be < limit on last page)
    "limit": 5,             // echoed from request
    "next_cursor": "eyJQ..."  // null when this is the last page
  }
}
```

### Pagination Rules

1. **First page**: Omit `cursor` parameter entirely
2. **Next page**: Pass `next_cursor` from previous response as `cursor` query param
3. **Last page**: `next_cursor` is `null` -- stop iterating
4. **Sort order**: Images sorted by `captured_at` descending (newest first)
5. **Cursor validity**: Cursors do not expire but may become invalid if underlying data is deleted
6. **Invalid cursor**: Returns `400 BAD_CURSOR`

## 4b. Authentication Contract `[MVP]`

> Based on ADR-007 (AWS Cognito User Pools + JWT). Authentication is handled at the API Gateway level via a JWT Authorizer. The Hono Lambda receives only validated requests with extracted user context.

### Authentication Flow

```
Client                 API Gateway              Hono Lambda
  |                        |                        |
  |-- GET /api/v1/farms --→|                        |
  |   Authorization:       |                        |
  |   Bearer eyJhbG...     |                        |
  |                        |-- Validate JWT ------→ |
  |                        |   (Cognito issuer,     |
  |                        |    audience, expiry)    |
  |                        |                        |
  |                        |-- If invalid: 401 ---→ |  (no Lambda invocation)
  |                        |                        |
  |                        |-- If valid: forward --→|
  |                        |   + JWT claims in      |
  |                        |   request context      |
  |                        |                        |
  |                        |                   Hono middleware extracts:
  |                        |                   - userId (Cognito sub)
  |                        |                   - isAdmin (email in ADMIN_EMAILS)
  |                        |                   Route handler checks membership
  |                        |                        |
```

### JWT Token Format

The `Authorization` header carries a Cognito-issued JWT access token:

```
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Relevant JWT claims** (extracted by Hono middleware):

| Claim | Type | Description |
|-------|------|-------------|
| `sub` | UUID | Cognito user identifier -- used as `userId` for membership checks |
| `email` | string | User's email address -- checked against ADMIN_EMAILS for admin access |
| `token_use` | `"access"` | Must be `access` (not `id`) |
| `exp` | number | Token expiry (Unix timestamp) |
| `iss` | string | Cognito User Pool issuer URL |
| `client_id` | string | Cognito App Client ID (validated by API GW) |

### Access Control Model

The system uses **role-based farm membership** rather than single-owner model:

| Role | Read | Write (beds, images, tags) | Manage members | Delete farm |
|------|------|---------------------------|----------------|-------------|
| `admin` | Yes | Yes | Yes | Yes |
| `manager` | Yes | Yes | Yes | Yes |
| `observer` | Yes | No | No | No |

**System admin** (email in `ADMIN_EMAILS` env var) can read all farms and bypasses membership checks for read operations.

## 6. Multipart Upload Contract

### Endpoint

```
POST /api/v1/beds/{bedId}/images
Content-Type: multipart/form-data
```

### Form Fields

| Field Name | Type | Required | Validation | Description |
|------------|------|----------|------------|-------------|
| `image` | File | Yes | JPEG only (`image/jpeg`), max 2,097,152 bytes (2MB). Validated by both content-type header and JPEG magic bytes (`FF D8 FF`). | The crop image file |
| `captured_at` | string | Yes | Valid ISO 8601 date-time with timezone. Must not be in the future (tolerance: +5 minutes for clock skew). | When the camera captured the image |
| `node_id` | string | Yes | Pattern: `/^[a-zA-Z0-9_-]{1,64}$/`. Alphanumeric with hyphens and underscores. | Camera node identifier |
| `trigger` | string | Yes | Exactly `"scheduled"` or `"motion"`. | What triggered the capture |
| `metadata` | string | No | Valid JSON string if provided. Max 4KB after parsing. Must be a flat or nested object (not array/primitive). | Camera metadata as JSON string |

### Metadata JSON Schema

When the optional `metadata` field is provided, it must parse as a valid JSON object:

```typescript
// All fields optional -- extensible for future sensor data
interface UploadMetadata {
  resolution?: string;          // e.g. "1280x720", "1920x1080"
  battery_pct?: number;         // 0-100 integer
  temperature_c?: number;       // ambient temp from camera node sensor
  signal_strength_dbm?: number; // LTE/WiFi signal strength
  firmware_version?: string;    // camera node firmware version
}
```

### Example Upload (cURL)

```bash
curl -X POST \
  "https://api.example.com/api/v1/beds/{bedId}/images" \
  -H "Authorization: Bearer {accessToken}" \
  -F "image=@photo.jpg;type=image/jpeg" \
  -F "captured_at=2026-03-17T09:00:00+09:00" \
  -F "node_id=node-north-01" \
  -F "trigger=scheduled" \
  -F 'metadata={"resolution":"1280x720","battery_pct":85}'
```

### Storage Key Generation

The server generates the S3 key from the upload context:

```
images/{farmId}/{bedId}/{YYYY}/{MM}/{DD}/{imageId}.jpg
```

Where `{YYYY}/{MM}/{DD}` is derived from `captured_at` in UTC.

### Validation Order

1. Check `Content-Type` is `multipart/form-data`
2. Check `bedId` exists and caller has write access (404 if not)
3. Check `image` field exists (400 if missing)
4. Check file size <= 2MB (413 if exceeded)
5. Check JPEG magic bytes `FF D8 FF` (415 if not JPEG)
6. Check required text fields: `captured_at`, `node_id`, `trigger` (400 if missing)
7. Validate field values (400 if invalid)
8. Parse `metadata` JSON if provided (400 if malformed)
9. Store to S3, write DynamoDB (503 if storage fails)

## 7. Signed URL Contract

### Generation Parameters

| Parameter | Value | Notes |
|-----------|-------|-------|
| Bucket | `litcrop-mvp-images` | S3 bucket in ap-northeast-1 |
| Key | `images/{farmId}/{bedId}/{YYYY}/{MM}/{DD}/{imageId}.jpg` | Full storage key |
| Expiry | 900 seconds (15 minutes) | Signed URL validity period |
| HTTP Method | `GET` | Read-only; no PUT or DELETE signed URLs exposed |
| Region | `ap-northeast-1` | Must match bucket region |

### Signed URL Format

```
https://litcrop-mvp-images.s3.ap-northeast-1.amazonaws.com/
  images/farm-001/bed-001/2026/03/17/{imageId}.jpg
  ?X-Amz-Algorithm=AWS4-HMAC-SHA256
  &X-Amz-Credential=...
  &X-Amz-Date=20260317T090000Z
  &X-Amz-Expires=900
  &X-Amz-SignedHeaders=host
  &X-Amz-Signature=...
```

### Client Usage Rules

1. **Do not cache signed URLs** beyond 15 minutes; request a fresh one via `GET /api/v1/images/{imageId}`
2. **Signed URLs are GET-only** -- clients cannot upload or delete via signed URLs
3. **Direct browser fetch** -- the signed URL points directly to S3; the browser fetches the image without going through the API Lambda
4. **CORS on S3 bucket** -- not required since signed URLs are simple GET requests (no preflight)

### Rate Limiting & Budget Controls (MVP)

| Layer | Scope | Limit | Reset | Error Code |
|-------|-------|-------|-------|------------|
| **Rate limit** | Per-user | 20 messages/hour | Sliding window | `RATE_LIMITED` |
| **Daily user budget** | Per-user (Cognito sub) | 50K input + 10K output tokens/day | Midnight UTC | `BUDGET_EXCEEDED` |

| **Conversation turns** | Per conversation | 20 turns max | New conversation | `RATE_LIMITED` |
| **Model lock** | Global | `claude-haiku-4-5-20251001` | N/A | N/A |

## 10. Thumbnail Contract `[MVP]`

> Based on FR-13 (Image Processing Pipeline). Thumbnails are server-generated 320px-wide JPEG derivatives stored alongside originals in S3.

### Thumbnail Generation Flow

```
1. Image uploaded to S3 (via POST /api/v1/beds/{bedId}/images)
2. S3 PutObject event triggers Thumbnail Lambda
3. Lambda reads original image from S3
4. Lambda resizes to 320px wide (maintaining aspect ratio)
5. Lambda writes thumbnail to S3 at predictable key
6. If generation fails, original image remains accessible
```

### Thumbnail Storage Key Convention

```
thumbnails/{farmId}/{bedId}/{YYYY}/{MM}/{DD}/{imageId}_thumb.jpg
```

Example:
```
Original:  images/farm-001/bed-001/2026/03/17/550e8400.jpg
Thumbnail: thumbnails/farm-001/bed-001/2026/03/17/550e8400_thumb.jpg
```

### Thumbnail URL in API Responses

The `thumbnail_url` field is present in:
- `LatestImage` (used in BedItem from GET /farms/{farmId}/beds)
- `ImageSummary` (used in GET /beds/{bedId}/images)
- `BedDetailImage` (used in GET /beds/{bedId})
- `GetImageResponse` (used in GET /images/{imageId})

```typescript
thumbnail_url: string | null;  // null if thumbnail not yet generated (async pipeline)
```

**Client behavior**:
- Use `thumbnail_url` for grid displays (Farm Overview tiles, Image History)
- Use `url` (full image) for full-screen viewing
- If `thumbnail_url` is `null`, fall back to `url` with CSS sizing

### Thumbnail Signed URL

| Parameter | Value |
|-----------|-------|
| Bucket | `litcrop-mvp-images` (same bucket, different prefix) |
| Key | `thumbnails/{farmId}/{bedId}/{YYYY}/{MM}/{DD}/{imageId}_thumb.jpg` |
| Expiry | 900 seconds (15 minutes) -- same as full image |
| HTTP Method | `GET` |
